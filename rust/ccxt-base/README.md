# CCXT — Rust

A Rust port of [CCXT](https://github.com/ccxt/ccxt), the CryptoCurrency eXchange
Trading library. Like the other CCXT targets, the Rust sources are **transpiled
from the TypeScript source of truth** (`ts/src`); the hand-written parts are the
runtime (`Value`, HTTP, crypto, rate limiter, the `types::*` structs) in the
sibling `ccxt-common` crate. Each transpiled exchange
struct (`Binance`, `Kraken`, …) exposes the unified methods with typed
signatures directly.

> **Status: work in progress.** The offline conformance suites pass (base,
> static request/response, id, prediction), but not every exchange method is
> exercised end-to-end and some signing primitives are intentionally
> unimplemented (see [Known limitations](#known-limitations)). Treat this as a
> preview, not a stable release. The crate is still `0.1.0`.

## Installation

```toml
[dependencies]
# The generated REST exchanges are behind a feature flag (see below).
ccxt = { git = "https://github.com/ccxt/ccxt", package = "ccxt", features = ["transpiled-base"] }
tokio = { version = "1", features = ["full"] }
```

## Quick start

Each exchange is one struct (`Binance`, `Kraken`, …) analogous to Go's typed
exchange structs. Unified methods take Rust primitives plus `Params` and return
`Result<T, ExchangeError>` with a native type (`Ticker`, `Order`, …).

```rust
use ccxt::{Binance, Params, ExchangeBase, ExchangeRuntime};

#[tokio::main]
async fn main() -> Result<(), ccxt::ExchangeError> {
    let mut ex = Binance::new(None);
    ex.load_markets(false, ()).await?;
    let ticker = ex.fetch_ticker("BTC/USDT", Params::none()).await?;
    println!("last = {:?}", ticker.last);
    Ok(())
}
```

Each exchange `Deref`s to the base `Exchange` (fields such as `id`, `has`,
`markets`). A `Box<dyn TypedExchange>` (`from_id`) carries the same base-spec
methods, plus `call::<R>(name, args)` to dispatch any method by name (`R = Value`
for methods without a typed signature).

## Feature flags

| feature | what it enables |
|---|---|
| *(default)* | the base runtime + hand-written base methods only (no venues) |
| `engine` | the transpiled base method surface (`exchange_generated`, prediction base) without any venue |
| `<id>` (`binance`, `kraken`, …) | one transpiled REST exchange; a derived venue's feature enables its parent (`binanceus` → `binance`) |
| `prediction-<id>` | one prediction-market exchange (prefixed because ids overlap the REST venues) |
| `all-exchanges` / `all-prediction` | every REST / prediction exchange |
| `transpiled-base` | `engine` + `all-exchanges` + `all-prediction` — the whole surface |

The base `Exchange` methods are always compiled; the features gate only the generated
modules. The crate builds with `--no-default-features` and with `--all-features`. The
user-facing crates (`ccxt`, `ccxt-pro`, `ccxt-prediction`) enable `engine` plus one `<id>`
feature per venue the user selected, which is what keeps a single-exchange build small;
the per-venue feature lists are generated by `build/rustTranspiler.ts`.

The transpiled WebSocket (`pro`) venues live in the sibling **`ccxt-pro`** crate,
split out so no single `rustc` invocation compiles the whole generated surface at
once. Add it as a dependency to use `watch_*`.

## Error handling

Expected failures surface as `Result<T, ExchangeError>` from the unified methods.
`ExchangeError::is()` / `is_a()` understand the CCXT class hierarchy, so you can
match on a base class:

```rust
match ex.fetch_ticker("BTC/USDT", Params::none()).await {
    Ok(t) => { /* … */ }
    Err(e) if e.is("NetworkError") => { /* transient — RequestTimeout, DDoSProtection, … */ }
    Err(e) if e.is("AuthenticationError") => { /* keys */ }
    Err(e) => eprintln!("{e}"),
}
```

## Rate limiting

`enableRateLimit` (on by default) drives a leaky-bucket limiter: requests are
spaced by `rateLimit` ms (weighted per endpoint). Disable it only if you throttle
externally.

## Prediction markets

Prediction venues (`kalshi`, `myriad`, `limitless`, `polymarket`, and the
prediction flavour of `hyperliquid`) live in the `ccxt::prediction` module and
share the `PredictionExchange` base (events → markets → outcomes).

## Known limitations

- **Unimplemented signing** — some exchange-specific signers (StarkNet/`paradex`,
  `lighter` zk-proofs, `dydx` protobuf tx, `apex` StarkEx, curve25519/`axolotl`)
  are **not yet ported**. They fail loudly with `NotSupported` rather than
  emitting an invalid signature, so those exchanges' private/trading endpoints
  are not usable yet. Public endpoints work.
- **Integer precision** — JSON integers above `u64::MAX` still fall back to
  `f64`; values up to `u64::MAX` are preserved losslessly (as strings when they
  exceed `i64`).
- The transpiler and dispatch layer are still being hardened; see the repo's
  Rust review notes for the current architectural roadmap.
