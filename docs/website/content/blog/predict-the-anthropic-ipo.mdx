Somewhere on the internet right now, people are betting real money on a wonderfully nerdy
question:

> **Will Anthropic or OpenAI IPO first?**

It's a real, live market on several prediction venues. And because it's binary — one of them
files first, the other doesn't — it's the perfect little playground for CCXT's
prediction-market support. Let's trade it.

## The one idea you need: prices are probabilities

Forget candles. On a prediction market, a **YES** share trades between `0.00` and `1.00` and
pays out **exactly 1.00 USDC** if the thing happens — otherwise zero. So the price *is* the
crowd's probability. "Will Anthropic IPO first?" trading at `0.55` means the market thinks
there's a **55%** chance. Buy 10 YES at `0.55` → you stake `5.50`; if Anthropic lists first
you collect `10.00`, if not you get `0`.

In CCXT terms it maps cleanly onto concepts you already know:

| Crypto exchange | Prediction exchange |
|---|---|
| a `symbol` (`BTC/USDT`) | an `outcome` handle (`ANTHROPIC_FIRST:YES`) |
| price in dollars | price = **probability, 0.00–1.00** |
| you sell to exit | it **settles** at 1.00 or 0.00 |

The data model has three layers, and the bottom one is what you trade:

- **event** — *"Which AI lab IPOs first?"* → `fetchEvents`
- **market** — the binary question → a `PredictionMarket`
- **outcome** — YES / NO → the tradeable handle (`outcome.outcome`)

## Step 1 — the fun part: let Dario pick your side 🐦

Here's a terrible, wonderful trading strategy: **read the CEO's tweets.** A founder who just
posted "excited to share we filed our S-1, roadshow next week" is telling you something the
order book may not have fully priced yet. A tiny keyword scanner turns that into a lean:

```ts
// YES on this market = "Anthropic IPOs first", so filing/listing chatter leans YES
const BULLISH = [ 's-1', 'roadshow', 'filing', 'filed', 'prospectus', 'listing', 'nasdaq', 'ipo' ];
const BEARISH = [ 'no plans', 'staying private', 'delay', 'next year' ];

function darioSignal (tweet: string): string {
    const text = tweet.toLowerCase ();
    let score = 0;
    for (const kw of BULLISH) if (text.indexOf (kw) !== -1) score += 1;
    for (const kw of BEARISH) if (text.indexOf (kw) !== -1) score -= 1;
    return (score > 0) ? 'buy YES' : ((score < 0) ? 'buy NO' : 'no lean');
}

darioSignal ('excited to share we confidentially filed our S-1 — roadshow soon');
// => 'buy YES'
```

> **Honesty check:** CCXT does **not** read Twitter/X. `darioSignal()` is a *bring-your-own-feed*
> stub — you pipe in tweet text from wherever you get it. Everything below that touches money
> is real CCXT. Your alpha being "a founder's typing habits" is a joke; the plumbing is not.

## Step 2 — read the odds, across every venue, with one loop

The same binary market is listed on more than one exchange — each with its own crowd, and
therefore its **own price** for the identical real-world event. In CCXT that isn't four
integrations; it's a loop over the *same* code.

```ts
import ccxt from 'ccxt';

async function readYes (venueId: string) {
    const ex = new ccxt.prediction[venueId] ();
    try {
        const events = await ex.fetchEvents ({ 'query': 'Anthropic IPO', 'sort': 'volume' });
        const market = events[0].markets[0];
        const yes = market.outcomes.find ((o) => o.label === 'Yes');
        const ob = await ex.fetchOrderBook (yes.outcome);        // yes.outcome is the tradeable handle
        return { venueId, 'bid': ob.bids[0]?.[0], 'ask': ob.asks[0]?.[0] };
    } finally {
        await ex.close ();
    }
}

const board = await Promise.all ([ 'polymarket', 'limitless', 'myriad' ].map (readYes));
```

One clean board, several regulatory regimes, zero special-casing:

```text
polymarket   YES 0.54 / 0.55   (~55%)
limitless    YES 0.51 / 0.52   (~52%)
myriad       YES 0.56 / 0.57   (~57%)
```

That normalization *is* the point: write the strategy once, and every venue speaks the same
dialect. Now look at those prices disagreeing — a door just opened.

## Step 3 — the free lunch: a cross-venue dutch book

A binary market has two shares, YES and NO, and **exactly one pays 1.00 USDC**. Buying a NO
share is the same as selling a YES share, so a NO costs `1 - (YES bid)`. If you can grab one
YES on the cheap venue and one NO on another for a combined cost **below 1.00**, you've locked
in profit no matter who actually IPOs first:

```ts
function findArb (board) {
    for (const a of board) for (const b of board) {
        if (a.venueId === b.venueId) continue;
        const noAsk = 1 - b.bid;         // buy NO on venue B = sell YES on venue B
        const cost  = a.ask + noAsk;     // one YES leg + one NO leg
        const edge  = 1 - cost;          // payout is always exactly 1.00
        if (edge > 0) console.log (`BUY YES @${a.venueId} + NO @${b.venueId} => +${(edge * 100).toFixed (1)}% risk-free`);
    }
}
```

It doesn't care who wins the IPO race. It collects the gap between two crowds who haven't
noticed they disagree.

> **The catch (why this isn't free money):** fees and slippage eat thin edges, both legs must
> actually fill, and your capital is locked until the market resolves. Real arbs are smaller
> and rarer than the toy numbers here — but a bot scanning every venue in a `Promise.all` finds
> them faster than you can refresh a tab. Efficient markets show **no** edge most of the time,
> and that's the normal, honest result.

## Step 4 — place the bet, and collect at settlement

Trading needs credentials (a wallet on the on-chain venues). Placing an order is one call —
`amount` in shares, `price` as a probability:

```ts
const poly = new ccxt.prediction.polymarket ({ privateKey, walletAddress });

// "buy 5 YES (Anthropic first), but only at 0.25 or better"
const order = await poly.createOrder (outcome, 'limit', 'buy', 5, 0.25);

// after one of them files — the fields that only exist because prediction positions RESOLVE
const [ pos ] = await poly.fetchPositions ([ outcome ]);
console.log (pos.resolved ? (pos.won ? `WON — payout ${pos.payout}` : 'lost') : `open, PnL ${pos.unrealizedPnl}`);
```

`resolved`, `won`, `payout` — a normal exchange has no concept of these, because a `BTC/USDT`
position never "comes true." A prediction position does. On venues that expose it (e.g.
Kalshi), `fetchSettlements()` closes the loop with the booked result.

When you actually wire this up, do it the safe way: place a **resting limit order that sits far
below the book so it cannot fill**, under a hard per-trade notional cap, then cancel it — the
same round-trip the other prediction examples use.

## Any language, and the terminal

The identical unified surface transpiles everywhere — prototype in Python, ship in Go, no API
to relearn:

```python
import ccxt.prediction            # prediction classes are async-only: ccxt.prediction.<id>

ex = ccxt.prediction.polymarket ()
events = await ex.fetch_events ({ 'query': 'Anthropic IPO' })
outcome = events[0]['markets'][0]['outcomes'][0]['outcome']
ticker = await ex.fetch_ticker (outcome)
print (f"market-implied: {ticker['last'] * 100:.1f}%")
await ex.close ()
```

Prefer the terminal? Every CLI takes `-p` / `--prediction`:

```bash
npm run cli.ts -- -p polymarket fetchEvents '{"query":"Anthropic IPO"}'
```

And to react the instant an S-1 hits the wire, venues with WebSocket support stream the same
shape via `watchTicker(outcome)` — a loop that pushes on every reprice.
