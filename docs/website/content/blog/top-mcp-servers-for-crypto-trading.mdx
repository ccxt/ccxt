MCP (the Model Context Protocol) lets an AI agent call real tools: pull prices, read order
books, place orders. Dozens of crypto MCP servers exist, so we picked five, installed each one
and ran the same live tests on all of them.

![Scorecard: five MCP servers rated on reach, streaming, context cost, key handling, write guard and maintenance. No server wins every column.](/images/blog/top-mcp-servers-for-crypto-trading/scorecard.png)

_At a glance: 5 servers × 6 criteria, from our live tests on 15 November 2026._

## How we picked the five

We searched GitHub, npm, MCP directories (Glama, Smithery) and community round-ups. We kept
servers that are open source, serve live data without keys, are maintained or lead their
niche, and each take a different approach.

| Server | Type | Version | GitHub stars |
| --- | --- | --- | --- |
| [ccxt-mcp](https://www.npmjs.com/package/ccxt-mcp) | Multi-exchange, official CCXT | 0.1.3 | in [ccxt/ccxt](https://github.com/ccxt/ccxt) (44.9k) |
| [OKX Agent Trade Kit](https://github.com/okx/agent-trade-kit) | Single exchange, official | 1.5.1 | 511 |
| [Bybit MCP Server](https://github.com/bybit-exchange/trading-mcp) | Single exchange, official | 2.1.28 | 44 |
| [TradingView MCP](https://github.com/atilaahmettaner/tradingview-mcp) | Analysis only, community | 0.8.1 | 5.3k |
| [doggybee/mcp-server-ccxt](https://github.com/doggybee/mcp-server-ccxt) | Multi-exchange, community | 1.2.1 | 145, the top result for "ccxt mcp" |

Left out: [Kraken CLI](https://github.com/krakenfx/kraken-cli) (its native installer could not
run in our sandbox), [Alpaca](https://github.com/alpacahq/alpaca-mcp-server) (keys needed for
every call), [lazy-dinosaur/ccxt-mcp](https://github.com/lazy-dinosaur/ccxt-mcp) (a third CCXT
wrapper) and [QuantDinger](https://github.com/OpenByteInc/QuantDinger) (13.8k stars, but its
MCP server is a front end to a self-hosted trading platform rather than a standalone server).

## How we tested

One US cloud machine, 15 November 2026, no API keys anywhere. Every server got the same tests:

- Startup and tool-list size.
- BTC/USDT ticker, 10-level book and 24 hourly candles on OKX: median of five calls, each price
  checked against the venue's REST API.
- Following BTC/USDT for 30 seconds: by WebSocket where the server offers it, by polling
  otherwise.
- A buy and a withdrawal attempt with no keys configured.
- Claude Sonnet 5.5 with one server attached, answering the same prompts.

Bybit's REST API blocks US traffic, so only its WebSocket streams could be measured.

## The five servers, tested

### 1. ccxt-mcp (official CCXT)

**Best for:** one agent across many exchanges.

```bash
claude mcp add ccxt -- npx -y ccxt-mcp
```

The official CCXT server serves public data on 104 exchanges with no setup, and balances and
orders once you add an account to its config file.

- **Good:** reached OKX, Kraken and Coinbase from one server, with the smallest responses and
  structured errors that say whether to retry. Background WebSocket streams return a merged
  snapshot, and a read can wait for the next change instead of polling. Keys never pass
  through the chat, and live trading needs `"trading": "live"` plus an order-size cap you must set (or explicitly waive).
- **Watch out:** young (v0.1.x). It lists trading tools even with no account unless
  `hideDisabledTools` is set, and it reported Bybit's geo-block as `RATE_LIMITED`.

### 2. OKX Agent Trade Kit (official OKX)

**Best for:** going deep on OKX, including algo orders, grid and DCA bots, options and Earn.

```bash
npm install -g @okx_ai/okx-trade-mcp
okx-trade-mcp --modules market   # public data, no keys
```

OKX's kit offers 180 tools in 11 modules you switch on as needed, plus a `--read-only` flag and
a demo profile.

- **Good:** the fastest OKX data, exact prices, keys kept in local profiles.
- **Watch out:** OKX only, no WebSocket tools so agents must poll, the heaviest responses, and
  default modules that cannot fetch a price. It does not ask for confirmation before an order;
  your client's approval prompt is the only check.

### 3. Bybit MCP Server (official Bybit)

**Best for:** Bybit derivatives traders outside the US.

```bash
claude mcp add bybit -- npx -y bybit-official-trading-server@latest
```

Bybit's server covers the whole V5 API in 400 tools, 23 of them usable without keys.

- **Good:** background WebSocket subscriptions, which worked from the US, and the strictest
  write path. Orders need `confirm: true` and a confirmation form the user must answer.
- **Watch out:** the REST API is blocked from our US host, and stream reads return raw message
  buffers with no way to wait for a change. Its tool list costs about 176k tokens per agent
  turn, with no way to load a subset.

### 4. TradingView MCP (community, analysis only)

**Best for:** screeners, technical analysis and backtests next to an execution server.

```bash
claude mcp add tradingview -- uvx tradingview-mcp-server
```

The most-starred project here (5.3k) has 37 read-only tools and cannot trade. It is not
affiliated with TradingView Inc.

- **Good:** no keys, rich scans and multi-timeframe reads, cached repeats in milliseconds.
- **Watch out:** no order book. Asked for Kraken, it silently returned Bitfinex prices. The
  PyPI release (0.8.1) lags GitHub (0.9.0).

### 5. mcp-server-ccxt (community, by doggybee)

**Best for:** public prices only.

```bash
claude mcp add ccxt-community -- npx -y @mcpfun/mcp-server-ccxt
```

The top GitHub result for "ccxt mcp" (145 stars) has 24 tools over a fixed list of 24
exchanges, last updated June 2025.

- **Good:** the lightest context cost; it covered OKX, Kraken and Coinbase.
- **Watch out:** order tools take your `apiKey` and `secret` as arguments, and in our test
  Claude asked the user to paste them into the chat. There is no OKX passphrase field, a 300 ms
  floor applies to every call, and its ticker cache returned the same price for 30 seconds of
  polling.

## Streaming: WebSockets vs polling

Only two servers stream market data: ccxt-mcp (on any exchange ccxt supports over WebSocket)
and Bybit. The others make the agent poll. Streaming wins on freshness and on checking in
later, not on call count.

![Freshness chart: streamed prices arrived 153–189 ms old; polled prices were about 700 ms old; one cached server served 15.3-second-old data.](/images/blog/top-mcp-servers-for-crypto-trading/streaming-freshness.png)

_Age = time from the exchange's own timestamp to arrival at the MCP client. Bybit was read every
250 ms, as it has no blocking read._

| 30 s following BTC/USDT | Tool calls | Price changes seen | Bytes returned |
| --- | --- | --- | --- |
| ccxt-mcp, WebSocket, wait for each change (OKX) | 188 | 21 | 101 KB |
| Bybit, WebSocket, read every 250 ms (Bybit) | 111 | 19 | 35 KB |
| ccxt-mcp, REST polling (OKX) | 102 | 16 | 41 KB |
| OKX Agent Trade Kit, REST polling (OKX) | 136 | 22 | 352 KB |
| mcp-server-ccxt, REST polling (OKX) | 98 | 0, served from cache | 88 KB |

**Checking in once after 30 seconds** is where the designs differ most. ccxt-mcp returned the
current ticker plus a count of 187 updates in 0.5 KB, and the last 36 trades in 10.7 KB. Bybit
returned 51 raw ticker messages in 24 KB and 65 trade messages in 64 KB. Only ccxt-mcp can
block a read until the next change, which suits waiting for an order fill. Only Bybit can
collect a fixed window of raw messages in one call.

**Agent test: "watch BTC/USDT for 20 seconds, report high, low and price changes"**

| Server | Agent turns | Input tokens | Price changes seen | What Claude did |
| --- | --- | --- | --- | --- |
| Bybit MCP Server | 2 | 0.48M | 18 | One `subscribeTickers` call that collected 20 s of ticks |
| OKX Agent Trade Kit | 18 | 1.33M | 11 | Polled the REST ticker about once a second |
| mcp-server-ccxt | 18 | 1.19M | 7 | Polled, clearing the stale cache before every read |
| ccxt-mcp | 19 | 1.45M | 5 | Read the stream snapshot 13 times; 124 updates arrived, most between reads |

In an agent's hands, Bybit's collect-for-a-window call won this task. ccxt-mcp's snapshots suit
checking in occasionally or waiting for a fill. For counting every tick it needs an event
stream such as `watchTrades`, and Claude did not reach for one.

## Security: what actually protects your money

Four servers keep API keys out of the conversation. One does not.

![Key-flow diagram: with ccxt-mcp, OKX and Bybit, keys stay in a local file the MCP server reads; with mcp-server-ccxt, keys are pasted into the chat, pass through the AI model as tool arguments and end up in chat history and logs.](/images/blog/top-mcp-servers-for-crypto-trading/key-flow.png)

_Where API keys travel, based on each server's tool schemas and our agent test._

Before trading with any of them:

- Create keys with **withdrawals disabled** and an **IP allowlist**.
- Start read-only, then move to testnet or demo: ccxt-mcp `"sandbox": true`, OKX
  `demo = true`, Bybit `BYBIT_TESTNET=true`.
- Keep your client's approval prompt on for every write tool.

## Verdict

**ccxt-mcp is the best default for most crypto agents.** It was the only server in our tests to
do all four of these:

- **Reach:** one install covered every venue we tried (OKX, Kraken, Coinbase), with 104
  exchanges available.
- **Key safety:** API keys never enter the conversation, and trading permissions live in a file
  the agent cannot edit.
- **Lean output:** the smallest responses we measured, so the agent reads less on every call.
- **Streaming:** WebSocket prices arrived 153 ms fresh against about 700 ms by polling, and a
  read can wait for a fill instead of polling.

It is not the fastest (OKX's kit was a few tens of milliseconds quicker on OKX data), it is
young (v0.1), and in our 20-second watch test Bybit's collect-a-window call beat it. Choose
differently in these cases:

![Decision tree: analysis only → TradingView MCP; most agents, any exchange → ccxt-mcp (default pick); deep on OKX → OKX Agent Trade Kit; Bybit only, outside the US → Bybit MCP Server; public prices with no keys ever → mcp-server-ccxt.](/images/blog/top-mcp-servers-for-crypto-trading/decision-tree.png)

In practice: use an exchange's own server only when you live on that one venue and want every
product it sells, and add TradingView MCP alongside ccxt-mcp when you want screeners and
backtests feeding your trades.

**Reproduce it** with the MCP TypeScript SDK; swap the command and tool name per server.

```js
import { Client } from '@modelcontextprotocol/sdk/client/index.js';
import { StdioClientTransport } from '@modelcontextprotocol/sdk/client/stdio.js';
const client = new Client({ name: 'mcp-bench', version: '1.0.0' });
await client.connect(new StdioClientTransport({ command: 'npx', args: ['-y', 'ccxt-mcp'] }));
const { tools } = await client.listTools();
const t = performance.now();
const r = await client.callTool({ name: 'get_tickers', arguments: { exchange: 'okx', symbols: ['BTC/USDT'] } });
console.log(tools.length, 'tools', Math.round(performance.now() - t), 'ms', r.content[0].text.length, 'bytes');
```
